# Kaggriculture 대회 우승을 위한 마스터 플랜

Kaggle의 **Kaggriculture** 대회는 30일(720턴) 동안 농장을 운영하며 자원을 관리하고, 수요와 공급에 따라 가격이 변하는 동적 시장에서 거래하여 상대방보다 더 많은 수익(Profit)을 내야 하는 복잡한 턴제 시뮬레이션 게임 대회입니다.

이 대회에서 우승하기 위한 상세한 전략과 3가지 AI 모델(Gemini Pro, Codex Plus, Claude Pro)을 활용하는 마스터플랜입니다.

## 1. Agent의 능력을 최대한 활용하는 방법

세 가지 뛰어난 AI 에이전트를 하나의 유기적인 팀처럼 활용하기 위해 **역할 분담**과 **효율적인 소통 체계**를 구축해야 합니다.

### 📁 단일 작업 폴더 구조 제안
모든 에이전트는 컨텍스트 단편화를 막기 위해 단일 작업 폴더를 공유해야 합니다.

```text
Kaggriculture/
├── agents/              # 제출용 봇 코드 (baseline.py, rl_agent.py, heuristic.py)
├── env_sim/             # 로컬 테스트를 위한 Kaggle 시뮬레이터 래핑 및 확장 환경
├── notebooks/           # EDA, 시장 가격 변동 분석, 시뮬레이션 로그 분석 (Jupyter)
├── docs/                # 프로젝트 지침, 아이디어, 에이전트 간 소통을 위한 회의록
│   ├── buzz.md          # 💡 에이전트 간 비동기 소통(Buzz) 게시판
│   └── experiments.md   # 실험 결과 및 리더보드 점수 트래킹
└── scripts/             # 유틸리티 (로컬 토너먼트 실행, 단일 파일 병합 스크립트 등)
```

### 🤖 각 Agent의 역할 부여
*   **Claude Pro (전략가 및 아키텍트):** 복잡한 게임의 룰을 분석하여 엣지 케이스를 찾고, 전반적인 메타 전략(예: 초반 토지 확장 vs 후반 고부가가치 동물 사육)을 수립합니다. 보상 함수(Reward Function) 설계와 프로젝트 지침 문서를 관리합니다.
*   **Codex Plus (수석 엔지니어):** Claude가 짠 전략을 버그 없는 고효율 Python 코드로 구현합니다. 특히 고도화된 룰베이스 엔진(Utility-based AI, FSM) 및 탐색 알고리즘(MCTS 등) 구현, 시뮬레이터 속도 최적화를 전담하며, RL은 추후 확장 목표로 삼습니다.
*   **Gemini Pro (데이터 애널리스트):** `notebooks/`에서 로컬 시뮬레이션 로그를 분석합니다. 상대방의 행동 패턴, 시장의 가격 등락 주기를 파악하고 시각화하여 다른 에이전트에게 새로운 인사이트를 제공합니다.

### 💬 Agent 간 소통 방법 (Buzz 시스템)
명령어 충돌과 컨텍스트 유실을 막기 위해 `docs/buzz.md` 파일을 활용한 **게시판 형태의 비동기 소통(Buzz)** 방식을 채택합니다.
*   **작동 방식:** 하나의 에이전트가 작업을 마친 후, 다음 에이전트가 무엇을 해야 할지 `buzz.md`에 To-Do나 이슈 형태로 기록(Buzzing)합니다.
*   **예시 흐름:** 
    1. **Gemini Pro**가 `buzz.md`에 남김: *"최근 1,000번의 로컬 시뮬레이션 결과, 300턴 부근에서 물 부족으로 작물이 폐사하는 현상 발견. 관개 시스템 로직 수정 요망."*
    2. **Claude Pro**가 확인 후 전략 수정: *"물 구매 임계치를 현재 보유량 10%에서 25%로 올리는 전략을 제안함."*
    3. **Codex Plus**가 이를 코드(`agents/heuristic.py`)에 반영하고 테스트 코드를 통과시킨 후 완료 처리.

## 2. 프로젝트 지침 작성 가이드

대회가 진행될수록 코드가 스파게티처럼 꼬이는 것을 막기 위해 명확한 지침(`docs/guidelines.md`)이 필요합니다. 지침에는 다음 내용이 포함되어야 합니다.

1.  **하향식(Top-Down) 개발 접근:** 처음부터 딥러닝/RL을 적용하지 않습니다. 가장 직관적이고 강력한 Rule-based(휴리스틱) 에이전트를 먼저 만들어 베이스라인을 구축합니다. 이후 이 로직을 모방 학습(Imitation Learning)하거나 튜닝하여 점진적으로 고도화합니다.
2.  **모듈화 및 엄격한 유닛 테스트:** '씨앗 구매', '시장 매도', '일꾼 고용' 등 각 행동은 독립적인 함수로 분리합니다. 720턴 중 단 한 번의 예외 오류로 봇이 멈추면 패배하므로, 엣지 케이스에 대한 유닛 테스트 통과를 코드 병합의 필수 조건으로 삼습니다.
3.  **실험 기록 의무화:** 로컬 환경에서 수정된 에이전트가 기존 에이전트를 상대로 승률이 55% 이상일 때만 제출합니다. 이 모든 과정은 `experiments.md`에 버전별 승률과 수익 평균치를 꼼꼼히 기록해야 합니다.
4.  **제출 포맷 자동화:** Kaggle 봇 제출은 보통 단일 Python 파일로 이루어집니다. `scripts/build_submit.py`와 같은 스크립트를 만들어 여러 모듈로 나뉜 코드를 제출 직전에 하나로 합치는 파이프라인을 유지합니다.
5.  **엄격한 턴 제한 시간(Time Limit) 관리:** Kaggle 환경은 턴당 실행 시간 제한(예: 1~5초)이 매우 엄격합니다. 시간 초과 시 패배 처리되므로, 프로파일링을 통해 실행 속도를 최적화하고, 시간이 지연될 경우 빠르게 기본 행동을 반환하는 Fallback 로직을 반드시 구현합니다.

## 3. 대회 기간 동안 명심할 핵심 세 가지 (Core Principles)

1.  **동적 시장(Dynamic Market)의 흐름을 지배하라**
    *   이 게임은 단순한 농사 게임이 아니라 경제 시뮬레이션입니다. 모두가 같은 작물을 수확해 팔면 가격은 폭락합니다. **상대방 모델링(Opponent Modeling)**을 통해 상대의 재고와 자금을 추적하여 시장 덤핑을 예측하고, 가격이 쌀 때 사서 창고에 묵혀두었다가 비쌀 때 파는 '재고 관리 및 트레이딩 전략'이 승패를 가릅니다.
2.  **강력한 로컬 토너먼트 환경이 곧 순위다**
    *   Kaggle은 하루 제출 횟수(5회)가 제한되어 있습니다. 리더보드 점수에 의존하지 말고, 수천 번의 자체 시뮬레이션을 돌려야 합니다. 공격적인 투자형, 극단적 수비형 등 다양한 더미(Dummy) 상대 봇들을 만들어, 우리 에이전트가 어떤 상황에서도 무너지지 않는지 평가하는 로컬 토너먼트 짐(Gym) 구축에 시간을 아끼지 마세요.
3.  **복잡성의 함정 피하기 (KISS: Keep It Simple, Stupid)**
    *   불확실성이 높은 시뮬레이션 환경에서는 훈련이 덜 된 복잡한 강화학습 모델보다, 탄탄하게 짜인 단순한 분기문(If-else)이나 FSM 기반 코드가 훨씬 강력할 때가 많습니다. 코드가 복잡해질수록 예상치 못한 턴에 에러가 발생하여 0점을 받을 확률이 높아집니다. 항상 단순함을 유지하며 안전망(Fallback 로직)을 확실히 구축하세요.
4.  **페이즈별(Phase-based) 전략 전환**
    *   720턴의 긴 게임은 단계별 전략이 필요합니다. 초반(성장 및 인프라 구축), 중반(시장 장악 및 스케일링), 후반(자산 현금화로 최종 수익 극대화)으로 페이즈를 나누어 에이전트의 행동 가중치(Utility score)를 동적으로 변경해야 합니다.
