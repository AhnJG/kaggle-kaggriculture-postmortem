## 1. 한 장 요약

**승부처 두 개다.**

**(A) 제출 슬롯 운영** — 최종 BT의 범위에 대해 공식 문서("마감 후 2주 에피소드")와 스태프 답변("전 기간 × 양쪽 최종 활성")이 **불일치한다.** 두 해석 모두에서 안전한 유일한 전략은 **"충분히 일찍 올리고, 그 뒤 절대 건드리지 않는다"**. 그리고 제출을 갈아치우면 (해석 B에서) 그 에이전트의 경기 이력이 사라진다. → **대회 전체 제출 5회 이하.**

**(B) 시장 실행** — 필드 관측이 명확하다. rank 3–20의 **필드 액션이 99~100% 동일**하고 차이는 시장 실행뿐이다. 우리가 이길 수 있는 지점은 농장이 아니라 시장이다.

**그리고 함정 하나**: 공개 테이프를 그대로 쓰면 이미 죽은 계통을 얻는다. 검증된 공개 노트북 포크의 상위권 점유율은 8/29 63.7% → 09-04 **0.1%**. 메타는 2~4일 주기로 회전한다.

→ **우리의 승부수는 "리플레이 → 테이프 추출 → 검증 → 우리 시장 레이어" 파이프라인의 자동화**다. 테이프 하나가 아니라 **테이프를 갈아끼우는 능력**이 자산이다.

**지금 당장**: §5 런북 S1부터. 첫 제출(v0)은 성능이 아니라 파이프라인 검증용이며 오늘~내일 안에 올린다.

### 3.2 아키텍처 — 테이프 + 가드 레이어

```
[테이프]      720턴 행동 배열 (리플레이에서 추출, O(1) 조회)
    │
    ├─ 잡초 자가복구      PLANT/BUILD 밑에 잡초 → DIG로 치환, 해당 유닛만 1턴 지연 (최대 8턴 추적)
    ├─ 예산 가드(72턴)     앞으로 72턴 소요 현금·재고 선계산 → 부족분만 고가부터 매도, protected_shed 보호
    ├─ 셰드 가드           매일 step%24==23에 질량보존식으로 초과분 강제 매도
    ├─ 시장 레이어         impact 정렬 · SELL을 BUY 앞으로 · 밀/비료는 앞 슬롯 제외 · 1턴 선행매도+부채장부
    ├─ 종료 청산           step 718에 전 품목 SELL 1,000,000
    ├─ 주문 클램프         병합 → append → [:10] (단일 지점)
    └─ align_hands         액션의 hands 길이를 실제 관측에 맞춤  ← 반드시 마지막
         │
    최외곽 try/except → 일꾼 수만큼 ["PASS"]
```

**설계 원칙 3가지**
1. 모든 가드는 `(obs, action, step) → action` 순수 함수. 하나씩 켜고 끄며 A/B 가능
2. `copy.deepcopy(obs)` 금지 (vCPU 1.6)
3. 제약(주문 10개 등)은 **단일 지점에서만** 강제

**ML은 좁게만**: 매도 타이밍 하나. 순수 self-play RL은 KILL(§4).

### 3.3 테이프 파이프라인 — 이게 우리 자산이다

메타가 2~4일 주기로 회전하므로 **테이프를 갈아끼우는 능력**이 테이프 자체보다 중요하다.

```
kaggle competitions episodes/replay  또는  kaggle/kaggriculture-episodes-index
      ↓  상위 레이팅 에피소드 필터
      ↓  steps[t+1][seat]["action"] 추출 (양 좌석)
      ↓  같은 계통 에피소드 3개 이상을 스텝별 다수결로 재구성
      ↓  bank-reproduction gate: 기록 seed로 엔진 재생 → 최종 뱅크가 기록과 일치해야 채택
      ↓  우리 가드·시장 레이어를 얹어 페어드 평가
      ↓  releases/
```
**bank-reproduction gate가 핵심이다.** 재생 결과가 기록 뱅크와 안 맞으면 그 테이프는 폐기한다.

**출처 기록 의무**: `opponents/README.md`에 URL · 저자 · 제출 ID · 에피소드 ID · 수집일 · 엔진 버전 · 라이선스. 수상 시 CC-BY 4.0로 소스 전부를 공개해야 하므로 처음부터 남긴다.

**법·규정**: 리플레이는 공식적으로 공개·다운로드 가능하고 스태프가 데이터셋을 제공하며 "IL/BC" 용도를 명시한다. **리플레이에서 추출한 행동(사실 데이터)을 쓰는 것과 남의 코드를 복사하는 것은 다르다. 우리는 전자로 간다.** 공개 노트북 코드를 쓸 경우 원본 페이지에서 라이선스를 먼저 확인한다(검토한 4개 전부 라이선스 미확인 상태).

### 3.4 시장 레이어 — 실제 알파

| 기법 | 내용 | 리스크 |
|---|---|---|
| **impact 정렬** | `수량 × (현재호가 − 판매후호가)` 내림차순으로 SELL 슬롯만 재배치. **`gross`로 정렬하면 거꾸로 된다** | 수량 불변 → **0** |
| **SELL을 BUY 앞으로** | 같은 턴에 판 돈으로 사려면 필수 | 0 |
| **밀·비료는 앞 슬롯 제외** | 상대가 `BUY_PRODUCT`할 수 있는 유일한 두 품목이라 상대 매수가 우리 가격을 올려준다. 그리고 **밀을 일찍 팔면 상대 사료값을 낮춰 현금난 라이벌을 구제한다** | 0 |
| **1턴 선행매도** | 다음 턴 예정 매도 일부를 당기고 부채장부로 정확히 차감(수량 보존). **2턴 앞은 실패로 확인됨** | 낮음 |
| **날짜 분산** | 일별 총량을 흡수율(딸기25/우유19/양털13/밀31) 이하로. **같은 턴 안의 분할은 무의미** | 0 |
| **로트 크기 = 경사 ÷ 흡수율** | 멜론 6 고정 / 우유 3·6·9 / 양털 4·8·12 / 비료 1·2·5·9 / **딸기는 급경사인데 큰 로트(28~34)** — 흡수율 최대라서 | 0 |
| **종료 청산** | step 718 전 품목 1,000,000 | **0, 수학적 약우세** |

### 3.5 생산 — 필드 컨센서스를 따르되 배치는 우리가

**따른다**: 소 8~10 / 양 4~9 / **거위 0** / 땅 3구획(day6 $1k, day10 $2k) / **4번째 구획 금지** / 밀·딸기·멜론 중심, 당근·토마토 배제 / 유휴 유닛턴은 전부 `CARE`
**우리가 개선한다**:
- **일꾼 하루 9~12명 평탄화** — 피보나치 절벽(13→233, 14→377) 회피. 같은 인력에 1,146코인 절약 사례 확인
- **셰드 중심 동심원 배치** — 파머·일꾼이 매일 셰드로 리스폰되므로 원거리 타일은 매일 왕복비가 붙는다
- **비료 조기 선점 + 지속 극세분할** — day2부터 1·2·5·9 로트로

### 3.6 판독 방어

우리는 이미 판독당한다고 가정한다. 우리 submission id만 알면 한 줄로 트리가 뽑힌다.

1. **분기 조건을 `market.inventory`로** — 공개 판독기의 63피처 메뉴에 시장 재고가 **없다**
2. **동점을 일부러 만들기** — 상관된 여러 변수의 합성으로 결정 → 변수명 귀속 실패
3. **모든 정렬 키·repair 로직 감사** — 한 참가자는 라우터를 t=226으로 늦췄는데 `dead_stock` repair가 가격순 정렬로 파는 바람에 **t=151에서 월드가 새어나갔다**(p=0.0005). "결정이 아니라고 생각한 코드"가 가장 강한 조건자였다
4. **공개 섀시를 쓰면 지문이 남는다** — 특정 섀시의 fork 지문이 최소 2팀에서 동일 관측됨
5. **상대 모델링은 리플레이로만.** 공개 코드와 필드 에이전트는 **719턴 중 697턴이 달랐던** 사례가 있다

## 9. 명심할 세 가지 (v2)

### 1. 제출 슬롯이 곧 점수다 — 그리고 제출은 정보 노출이다
최종 BT 범위가 공식 문서와 스태프 답변 사이에서 불일치하므로 **양쪽에서 안전한 "일찍 올리고 안 건드린다"**로 간다. 대회 전체 제출 5회 이하, Slot A는 09-22에 넣고 끝까지 손대지 않는다. 그리고 **제출할 때마다 우리 리플레이가 공개되고 97% 정확도로 판독당한다.** 상금권 폭이 72점인데 노이즈가 ±25~50이므로 목표는 "10위"가 아니라 **"10위 + 100점"**이다.

### 2. 농장이 아니라 시장에서 이긴다
rank 3–20의 필드 액션이 99~100% 동일하다. 우리가 만들 차이는 **슬롯 순서, 1턴 선행매도, 흡수율 정합, 종료 청산**에 있다. 같은 턴 안의 분할은 무의미하고, 밀·비료를 앞 슬롯에 올리면 상대를 돕는다. 그리고 **이미 이기는 상대의 마진이 아니라 지는 소수 경기가 레이팅을 결정한다.**

### 3. 엔진이 진실이고 공식 문서도, 남의 노트북 서술도 아니다
같은 공식 페이지 안에서 급수 주기가 모순되고, 공식 Quick Start 예제에는 버그가 있으며, 한 노트북의 서술("8c/6s")과 실제 테이프(10c/4s)가 다르고, 다른 노트북은 마크다운이 자랑하는 기능이 코드에서 꺼져 있었다. **재현 명령 없는 숫자는 FACT가 아니다.** 그리고 무음 실패(불법 액션·셰드 소멸·주문 절삭)는 예외를 안 내므로 **계측하지 않으면 없는 것처럼 보인다.**
