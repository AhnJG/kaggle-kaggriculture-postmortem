# 내가 가진 자원으로 어떻게 했어야 했나

> [AI 활용 반성](ai-usage-lessons.md)은 무엇이 틀렸는지를 모았다. 이 문서는 그 반대 질문에 답한다.
> **같은 사람, 같은 장비, 같은 에이전트, 같은 4주로 무엇을 다르게 했어야 했나.**
>
> - 작성: 2026-10-27, 최종 순위(1,498위 / 10,148팀)와 상위권 write-up 을 읽은 뒤.
> - 결과를 알고 쓴 계획이라 사후 판단(hindsight)이 섞여 있다. 그래서 각 제안에 **당시에도 알 수 있었던 근거**를 함께 적었다.
> - 상위권 팀의 수치는 그 팀들의 보고(`[COMMUNITY]`)이고 재현하지 않았다. 이 계획이 실제로 몇 위를 냈을지는 알 수 없다(§6).

## 1. 내가 가진 자원

| 자원 | 실제로 있던 것 | 이번 대회에서 쓴 방식 |
|---|---|---|
| 사람 | 1명. 코드를 직접 쓰지 않음. 방향·규칙·승인·제출 | 같음 |
| 기간 | 09-02 계획 시작 ~ 09-30 23:59 UTC 마감, 약 4주 | 계획에 5일, 첫 제출 09-07 |
| 제출 | 하루 5회, 최신 2개만 활성, 최종 순위는 활성 제출끼리의 Bradley-Terry | 26회. 마지막 이틀에 슬롯 6회 교체 |
| 로컬 장비 | MacBook Air M3 (8코어, 팬 없음, 24GB). 동시 경기 6개까지 | 로컬 경기 실행, 짝 대결 |
| Kaggle CPU 커널 | private 커널 5개 동시, 커널당 CPU 4개. 판당 Mac 의 약 2.4배 느림(EXP-033 파일럿 실측) | 09-27부터 대량 경기 실행에 사용 |

| AI 에이전트 | Claude Opus 5→5.5, Codex(GPT-5.6 Sol), Gemini 3.1 Pro·3.8 Flash(Antigravity), GPT-5.6 Sol(ChatGPT). 각각 사용량 한도 있음 | 4종 동시 운영, 조율 문서 약 440개. Codex 는 09-30 사용량 소진 |
| 데이터 | 실전 리플레이를 내려받을 수 있음. 실전 경기를 tape 로 정확히 재생하는 도구(163/163 일치) | 상위권 tape 대량 수집은 09-28(LB 2400 이상 743개) |
| 엔진 지식 | 엔진 버전 고정, 무음 실패 표(초과 주문 절삭, 셰드 초과 소멸 등) | 검증 gate 에만 사용 |

정리하면 **GPU 와 리플레이 데이터가 있었는데 둘 다 학습에 쓰지 않았고, 에이전트는 많았는데 판단이 한곳에 몰렸다.**

## 3. 같은 자원으로 했어야 할 계획

### 1주차 (09-02~08): 기준선과 평가기부터

| 할 일 | 당시에도 알 수 있었던 근거 |
|---|---|
| 첫 이틀 안에 공개 최강 노트북을 그대로 제출해 기준선을 잡는다. 계획서는 1개, 1쪽 | 09-06 문서 검토에서 이미 "상위권은 tape 를 재생한다"를 알았다. 실제 첫 큰 상승(09-10)이 바로 이것이었다 |
| 상위권 리플레이 수집을 첫 주에 자동화하고 매일 돌린다(Antigravity 담당) | 수집 도구와 tape 정확 재생 도구는 이미 만들었다. 대량 수집이 09-28로 늦었을 뿐이다 |
| 로컬 지표가 실전 순서를 맞히는지 먼저 잰다. 공개 봇 3~5개를 제출해 실전 점수를 얻고, 로컬 짝 대결이 그 순서를 맞히는지 본다 | 09-07 v0 이 로컬에서 starter 를 크게 이기고도 실전 337점이었다. 우리 계약(§7.1)도 이 "삼중쌍 표"를 요구했다 |
| 제출 정책을 이때 고정한다: 슬롯 A 는 안정형, B 는 다른 전략, 판정을 넘어 제출할 조건, 마지막 72시간 교체 상한 | 최신 2개만 활성이라는 규칙은 처음부터 알았고, 최종 순위가 활성 제출끼리의 경기만 센다는 것(F-T12)도 09-12 에 확인했다 |

### 2주차 (09-09~15): 행동 복제(BC) 기준선을 Kaggle GPU 에서

| 할 일 | 근거 |
|---|---|
| 상위 팀 리플레이로 작은 행동 복제 모델을 만든다. 처음에는 약 1M 파라미터 수준 | 09-03 우리 [흡수 전략 문서](../plan/kaggriculture_strategy_transfer.md)가 BC 를 "확실한 상위권"으로 평가했다. 상위권 사례: 13위 약 0.95M(RTX 5090 1장, 약 10시간), 19위 약 0.9M CNN 앙상블, 7위 RTX 5090 1장에서 사전학습 약 50분 |
| 학습은 Kaggle 무료 GPU 에서 한다. Mac 은 경기 실행, Kaggle CPU 커널은 대량 평가 | T4 는 RTX 5090 보다 여러 배 느리다 `[추정]`. 그래서 모델을 작게 시작하고, 주간 GPU 한도 안에서 하루 몇 시간씩 나눠 쓴다 |
| 라벨은 실제로 체결된 행동만 쓴다 | 우리는 무음 실패 표(초과 주문 절삭 등)를 이미 갖고 있었다. 4위·9위가 같은 정제로 큰 이득을 봤다고 보고했다 |
| 학습 데이터의 정합성은 tape 재생 도구로 확인한다(재생한 잔고 = 공식 잔고) | 163/163 정확 재생 도구가 이미 있었다. 3위도 공식 잔고가 재현되지 않는 경기를 버렸다 |

## 4. 에이전트를 어떻게 썼어야 했나

| 이번 | 했어야 할 것 |
|---|---|
| 4종 동시 운영, 코디네이터 3번 교체 | 판단 1(Claude) + 구현 1(Codex: BC 학습·평가 파이프라인) + 수집 1(Antigravity: 매일 리플레이). Sol 외부 검토는 마지막 사흘이 아니라 첫 제출부터 |
| 조율 문서 약 440개, 실험 하나에 약 7개 | 지시서는 한 장짜리 양식의 칸만 채운다 |
| 상수 ±1 변형 수백 개를 로컬 지표로 탐색 | 평가기 검증을 통과하지 못한 지표로는 탐색하지 않는다. 그 에이전트 시간을 BC 에 쓴다 |
| 사용량 소진·컨텍스트 리셋 때 즉흥 대응 | 에이전트별 하루 예산과 인수자를 상태 문서에 미리 적는다 |

**코드를 직접 쓰지 않는 사람이 BC 파이프라인을 검증하는 법.** 에이전트가 쓴 학습 코드는 이번 대회의 도구 버그(10건)처럼 조용히 틀릴 수 있다.
그래서 결과 숫자 대신 **답을 아는 시험**을 요구했어야 한다.

- 배치 하나를 외우게 해서 손실이 0 근처로 가는지 본다. 안 가면 모델이나 코드 문제다.
- 학습 라벨로 경기를 다시 재생해 공식 잔고가 나오는지 본다.
- 평가 경기마다 행동 수와 오류 수를 함께 기록하고, 결과를 쓰기 전에 무작위로 몇 판을 직접 연다(C9 에서 효과가 확인된 방법).

## 5. 무엇을 포기했어야 했나

시간은 늘지 않으므로, 위 계획은 아래를 버려야 들어간다.

| 포기할 것 | 쓴 시간 | 결과 |
|---|---|---|
| 계획서 3개 교차 검토 (1~2일로 줄임) | 5일 | 핵심 전제(규칙기반 실행기)는 09-10 에 폐기 |
| 직접 짠 규칙기반 봇 개선 | 3일 | 공개 상위 봇 상대 0/0/400 |
| 09-16~18 정합성·귀인 작업 | 3일 | 측정은 정밀했지만 제출 개선 0 |
| 상수 ±1 대량 탐색(EXP-025, EXP-036) | 약 2일 (09-26~27) | 지던 상대에게 ±1 변형 0/171, d157 ±1 158개 변형 FAIL |
| 상대 예측·생산 재설계(EXP-045~057) | 약 2일 (09-28~29) | 개선 후보 전부 FAIL |

계획 기간을 이틀로 줄이는 것까지 합치면 약 2주가 나온다. 2주차 BC 기준선과 3주차 데이터 갱신을 넣기에 충분한 시간이다.

## 6. 이 계획이 통했을지에 대한 불확실성

- **BC 가 우리 자원에서 어디까지 갔을지는 모른다.** 작은 컴퓨트로 상위권에 오른 팀들은 ML 경험이 있었을 가능성이 크다 `[추정]`. 우리는 학습 코드를 에이전트가 쓰고 사람이 검증해야 했다.
- **Kaggle GPU 한도와 속도는 추정이다.** 주간 한도는 공식 문서에 수치가 없고, T4 와 RTX 5090 의 속도 차이도 직접 재지 않았다.
- **상위권 수치는 그 팀들의 보고다.** 재현하지 않았다.
- **확실한 쪽은 1주차와 4주차다.** 공개 최강 봇을 일찍 내는 것, 평가기를 먼저 검증하는 것, 마지막 72시간에 슬롯을 지키는 것은 BC 성패와 무관하게 이번 기록이 직접 뒷받침한다.

## 한 줄로

**엄격한 실험 대신 맞는 방향과 맞는 평가기에 먼저 시간을 썼어야 했다.** 공개 최강 봇으로 첫날 기준선을 잡고, 쓰지 않은 Kaggle GPU 로 리플레이 행동 복제를 시작하고, 마지막에는 슬롯을 지켰어야 했다.
